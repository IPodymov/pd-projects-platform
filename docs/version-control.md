# История и возврат к рабочей версии

Первый коммит фиксирует текущий рабочий код целиком: до него репозиторий не содержал коммитов. Второй добавляет документацию. Это исходная контрольная точка; прежние промежуточные состояния не восстановлены задним числом.

Последующие изменения оформляйте отдельными коммитами по задачам после проверки тестов. Просмотр истории:

```sh
git log --oneline --decorate
git show <commit>
```

Чтобы отменить конкретное последующее изменение с сохранением общей истории:

```sh
git revert <commit>
# Разрешить конфликты, если появились, и выполнить проверки.
git push origin main
```

Для изучения старой версии без изменения текущего checkout:

```sh
git worktree add --detach ../pd-platform-inspect <commit>
```

Такой checkout не следует запускать против текущей БД без проверки совместимости схемы. Git хранит код, миграции и разрешённые fixtures, но не локальную PostgreSQL, S3, .env или загруженные файлы. Возврат кода не восстанавливает данные. Перед изменениями схемы сохраняйте отдельную резервную копию БД и файлов; обратные миграции оценивайте отдельно, особенно если они удаляют данные. Production seed не является резервной копией.

Не используйте force push и reset --hard для обычного отката общей main: revert создаёт явный коммит отмены. Исходный root commit отменять целиком не следует — это удалит весь проект из checkout.
