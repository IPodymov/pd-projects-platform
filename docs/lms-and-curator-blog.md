# Курсы, материалы и журнал кураторов

## Исследование и выбранные сценарии

Moodle организует курс как последовательность учебных ресурсов и активностей: преподаватель редактирует содержание, учащийся открывает материалы и отправляет практическую работу, преподаватель оценивает результат. Canvas также различает материалы курса и способы отправки работы: текст, файл, ссылка. Для этой платформы выбраны уроки, отдельные файлы и существующий цикл задания «черновик → отправлено → принято / доработка». Сложные тесты, сертификаты и SCORM не входят в эту реализацию.

Источники:
- [Moodle: страница курса](https://docs.moodle.org/503/en/Course_homepage).
- [Moodle: задания и отправка файлов](https://docs.moodle.org/402/en/mod/assignment).
- [Canvas: создание online assignment](https://community.instructure.com/en/kb/articles/660671-unknown).

Хабр использует блочный WYSIWYG-редактор с Markdown-командами, загрузкой изображений и отдельными настройками публикации. Вступление в ленте можно задавать отдельно от тела статьи. Есть локальное автосохранение; серверный черновик с ID позволяет продолжить работу на другом устройстве. Публикация включает выбор темы/хаба и других метаданных.

На нашей платформе применены: отдельный лид, тема, автор, Markdown с заголовками, списками, цитатами, кодом и изображениями, импорт MD/TXT, серверные черновики, предпросмотр, публичная страница статьи и явная публикация. Изображения добавляются после сохранения черновика. Полный WYSIWYG, локальное автосохранение, рейтинги и комментарии пока отсутствуют. Публикации создаются в журнале платформы; интеграция с аккаунтом или API Хабра не выполняется.

Источник: [официальная документация редактора Хабра](https://habr.com/ru/docs/help/wysiwyg/).

## Пользовательские сценарии

### Преподаватель

1. Открыть «Курсы» → «Создать», выбрать своё учреждение, указать название и описание.
2. В кабинете курса добавить уроки (текст Markdown) и/или практические задания с критериями и сроком.
3. Загрузить учебные файлы в «Материалы курса».
4. Опубликовать курс. После публикации структура уроков и заданий неизменяема.
5. Записать учеников своих классов, проверять их отправки, принимать работы или возвращать с замечаниями.
6. Для собственного прохождения нажать «Записаться», выбрать доступный класс своего учреждения, проходить уроки и отправлять задания. Работу преподавателя может проверить куратор или другой сотрудник с доступом к классу.

Администратор учреждения и куратор также управляют курсами. Полномочия преподавателя на авторство ограничены его учреждением; запись и проверка учеников — его классами.

### Студент

1. Выбрать опубликованный курс своего учреждения и записаться через свой класс.
2. Читать уроки, отмечать их пройденными, скачивать учебные материалы.
3. Загрузить собственный файл курса. Его видят автор и преподаватели учреждения, другие студенты доступа не получают.
4. Отправлять результаты задания через «Моя работа», получать замечания, отправлять новую версию при доработке.
5. В своём проекте создавать документы и загружать версии, скачивать их и восстанавливать старые. Файлы доступны только участникам проекта и сотрудникам с доступом к его классу.

Прогресс: число завершённых уроков и принятых обязательных заданий, делённое на общее число уроков и обязательных заданий. 100% присваивается только после выполнения всех условий; запись становится завершённой. Отметка урока — подтверждение пользователя, не измерение времени чтения. Файлы курса сами по себе не засчитывают практическое задание. Архив курса закрывает новые загрузки и прохождение, история сохраняется.

### Куратор

1. Открыть «Журнал» → «Новый черновик».
2. Указать заголовок, постоянный адрес, тему, аудиторию и вступление для ленты.
3. Написать Markdown или импортировать MD/TXT до 1 МБ.
4. Сохранить черновик. Добавить PNG/JPEG до 5 МБ: ссылка вставится в текст; повторно сохранить текст.
5. Проверить предпросмотр и опубликовать. Статья открывается по `/articles/:id`.

Автор назначается сервером. Куратор редактирует и публикует собственные статьи; администратор платформы имеет доступ ко всем. Черновики скрыты от читателей; публичные статьи доступны без входа, статьи для участников — после авторизации. Архивирование скрывает статью и её изображения от читателей. Старые статьи без автора подписаны «Редакция платформы».

## Файлы и доступ

Файлы проектов и курсов: TXT, MD, CSV, DOCX, PPTX, PDF, PNG, JPEG до 20 МБ. Для текста требуется UTF-8. Для Office проверяется структура ZIP, лимит распаковки и отсутствие DTD/ENTITY. Для PDF и изображений проверяется сигнатура. Предпросмотр TXT, Markdown, CSV, PDF и изображений в курсах и проектах также запрашивает файл через API с проверкой прав; временный URL браузера отзывается при закрытии. DOCX/PPTX доступны для скачивания и сравнения извлечённого текста в проектах. Скачивание осуществляется через API с проверкой прав; приватные ссылки S3 не выдаются. PDF и изображения не поддерживают сравнение текста документов проекта.

Изображения статьи проверяются Pillow и перекодируются в JPEG без исходных метаданных. Поддерживаются изображения до 20 мегапикселей. Просмотр каждого изображения повторяет проверку доступа к статье. Raw HTML в Markdown выключен; опасные протоколы ссылок блокирует markdown-it.

## Запуск изменений

Применить миграции backend: `make migrate` в работающем локальном Compose либо `python manage.py migrate` в настроенном backend. Перезапустить worker после изменения backend-кода. OpenAPI и TypeScript-клиент обновлены через `make schema`.

Новые ресурсы: `/api/v1/course-lessons/`, `/api/v1/course-materials/`. Урок завершает действие `complete/`, файл скачивается через `download/`. Изображения статьи: `publications/:id/upload_image/` и `publications/:id/image/?image=:uuid`.
