# Права, безопасность и метрики

## Матрица доступа

| Область | Platform admin | Institution admin | Curator | Teacher | Student |
|---|---|---|---|---|---|
| Создание учреждения | да | нет | нет | нет | нет |
| Управление классами | все | своё учреждение | чтение | назначенные, чтение | свои, чтение |
| Приглашение сотрудника/назначение преподавателя | все | своё учреждение, teacher/curator | нет | нет | нет |
| Импорт/приглашения учащихся и XLSX | все | своё учреждение | назначенные учреждения | назначенные классы | нет |
| Проекты/задания | все | своё учреждение | назначенные учреждения | назначенные классы | участие в проекте |
| Принятие результата | все | своё учреждение | назначенные учреждения | назначенные классы | нет |
| Изменение расписания | все | своё учреждение | назначенные учреждения | чтение назначенных классов | чтение своих классов |
| CRM | все | своё учреждение | назначенные учреждения | назначенные классы | агрегаты без данных, раздел скрыт UI |
| Django Admin | superuser | нет | нет | нет | нет |

Роли совмещаются через назначения. require_class, require_institution и project_access используются и в queryset, и в services. UI hiding — удобство, сервер решает доступ. Для Classroom, Enrollment, Project, Task и staff назначения нельзя передать чужие FK для обхода scope. Конкурентные operations требуют PostgreSQL; SQLite только облегчённые тесты.

## Регистрация и администрирование аккаунтов

Самостоятельная регистрация требует кода на почту и не выдаёт роли или членства. Управление аккаунтами доступно администраторам с серверной областью доступа; новые подтверждённые аккаунты без назначений добавляются по точному email. Подробные правила, ревизии и ограничения — [registration-and-accounts.md](registration-and-accounts.md).

## Приглашения

- Token secrets.token_urlsafe(32), SHA-256 в DB. Одноразовое принятие под select_for_update. Токен передаётся в fragment URL, а не query/path; браузер убирает fragment после чтения и держит только в памяти. При обновлении страницы нужно снова открыть письмо.
- Код отправляется исключительно на Invitation.email. Совпадающий введённый email не является доказательством; клиент вообще не выбирает получателя кода. HMAC кода использует server secret и token hash. Срок кода 10 минут, повторная отправка не чаще минуты, максимум 10 ошибочных подтверждений, глобальные DRF throttles в Redis.
- Срок приглашения 7 дней. Отзыв/исправление email закрывает старый invite и код. Beat удаляет ciphertext истёкших приглашений, дополнительно очистка происходит при mail/export/read приглашений. Исходный токен для повторного XLSX доступен только как Fernet ciphertext до закрытия приглашения; ключ из environment отдельно от DB. Потеря ключа означает необходимость явного отзыва/перевыпуска, не молчаливое восстановление.
- Новый пароль проверяет Django password_validation. Временные пароли и self-selected roles отсутствуют. Existing user обязан войти; после кода его почта подтверждается, существующий пароль не меняется.
- После регистрации преподаватель не исправляет email. Владелец использует authenticated email-change request с текущим паролем, затем код на новый адрес. Старые запросы отзываются. Email case-insensitive unique constraint предотвращает дубликаты.
- Development принудительно Mailpit без production SMTP credentials. Test in-memory email. Worker получает invitation id и шифрованный код; не plaintext token/code в task arguments. Task logging не содержит письма или plaintext secrets.

Export требует staff scope, пишется audit, no-store и не сохраняется по публичной ссылке. Только pending/unexpired ссылки; registered/accepted/revoked/expired пустые. Формульные префиксы Excel экранируются. XLSX/CSV ограничены 2 МБ, 500 строк, expanded archive лимит. Дубликаты email, чужие существующие accounts и несовпадение ФИО для email отклоняются. Совпадение ФИО никогда не объединяет людей.

## Файлы и расписание

Документы максимум 20 МБ; text только UTF-8, Office ZIP с проверкой обязательной структуры и expanded limit 50 МБ. Оригинал хранится в S3 под случайным ключом. Diff — структурированные строки, Vue экранирует их. Непроверенный HTML не встраивается. Приватная скачка после проверки project_access; нет публичного MEDIA_URL route. Антивирус/карантин и квоты пользователя ещё не реализованы.

Online lesson URL только HTTPS без userinfo. При переходе onsite старая URL очищается; online очищает аудиторию. На форме отображается локальное время браузера, оригинал UTC и timezone серии сохраняются. Series — weekly, не произвольный RRULE. Пересечения teacher/classroom/location+room одного учреждения проверяются в транзакции, блокируются teacher и institution для сериализации создателей в этих областях. Занятие класса может быть связано с Course того же учреждения: учащийся дополнительно должен быть записан на курс, иначе событие/online URL скрыты. Course-only и события нескольких классов ещё не реализованы.

## Определения CRM

- Registered — уникальные пользователи с историческим StudentMembership в видимых классах. Это не online.
- Email verified — registered с email_verified_at.
- Logged in during period — уникальные участники с LoginEvent в [from,to). Login events — число событий реального входа; last_login не используется как замена истории.
- Educationally active — уникальные учащиеся с LearningActivity в [from,to): task.submitted, course.submitted, document.uploaded или project.updated. Обычный login не записывает LearningActivity. Изменение проектного описания считается проектным учебным действием; прочтение материалов — нет.
- Progress — число Task с хотя бы одной accepted Submission / все Task × 100, округление до целого; без заданий 0%. Submitted и accepted показываются отдельно. Поздняя доработка не отменяет уже принятую другую отправку.
- Overdue — due_at < now и ни одного accepted результата. Attention projects — хотя бы одно такое задание.
- Attendance present — присутствие на занятиях, попавших в период.
- Workshop confirmed/waiting/attended — отдельные показатели, не добавляются в основное обучение.

Фильтры institution/classroom/teacher пересекаются с scope сотрудника, не расширяют его. Course фильтр выбирает учащихся/классы с Enrollment в курсе; задания текущей модели привязаны к проекту/классу, не конкретному курсу, поэтому это срез enrolled cohort, а не точная аналитика заданий данного курса. Period применяется к login/activity/attendance; registered/enrollments/projects/задачи — текущие totals, workshops — totals. Проектная аналитика — срез когорты, курсовые работы/задания дополнительно ограничены выбранным course. Максимум периода 366 дней, default последние 30. Каждая выдача содержит updated_at. Показатель «сейчас онлайн» отсутствует.

Audit хранит назначения, приглашения/почту, импорт/экспорт, проверки, расписание и посещаемость. Пароли/токены/коды/request bodies не записываются. Audit не является tamper-proof external ledger; глобальный DB администратор может менять БД. Production-ограничение удаления доступно через API/Admin.

Outbox handler реально выполняется внутри Celery task process_outbox с soft/hard timeout 70/90 секунд (декораторы вложенных задач сами по себе не ограничивают прямой вызов). Worker использует concurrency=2, max-memory-per-child=256 MiB после задания и recycling; Compose ограничивает контейнер 1 GiB. На Railway установите соответствующий лимит памяти сервиса. Это ограничение времени и размера, не заявление о выполненном security audit Office-парсеров.
